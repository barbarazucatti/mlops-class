# Aula 4 - Pipeline de MLOps Para Operacionalização e Monitoramento de IA Generativa com LLM e RAG
# Instruções Para Execução do Projeto na AWS (EC2 + Terraform + VSCode Remote-SSH)

# Nota: O LLM (BERT) é executado no container da app, via biblioteca transformers (PyTorch CPU).
# Nesta versão os containers rodam numa instância EC2 na AWS, e não no Docker Desktop do seu computador.
# Você edita os arquivos e roda os comandos pelo VSCode conectado à EC2, e acessa as aplicações
# no navegador do seu computador normalmente (localhost), através de um túnel SSH.

# ATENÇÃO: a instância gera custo enquanto estiver ligada. Ao terminar, execute o passo 9 (terraform destroy).


# 1- Pré-requisitos (instalar uma única vez):

# - Conta na AWS
# - Terraform: https://developer.hashicorp.com/terraform/install
# - AWS CLI:   https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html
# - VSCode com a extensão "Remote - SSH" (Microsoft)

# No macOS, com Homebrew:

brew install hashicorp/tap/terraform awscli

# 2- Configure as credenciais da AWS:

# No console da AWS, crie um usuário IAM com as políticas AmazonEC2FullAccess e AmazonSSMReadOnlyAccess e gere uma Access Key
# (IAM > Users > seu usuário > Security credentials > Create access key > Command Line Interface).
# Não use access keys do usuário root da conta.

aws configure

# AWS Access Key ID:     <sua access key>
# AWS Secret Access Key: <sua secret key>
# Default region name:   us-east-1
# Default output format: json

# Teste:

aws sts get-caller-identity

# 3- Abra o terminal, navegue até a pasta terraform do projeto e crie a instância:

cd terraform
terraform init
terraform apply

# Digite "yes" para confirmar. O Terraform vai:
# - criar a instância EC2 (Ubuntu 24.04) e instalar Docker e Docker Compose
# - liberar o acesso SSH apenas para o seu IP atual
# - gerar a chave SSH em ~/.ssh/mlops-aula4.pem
# - copiar os arquivos do projeto para a pasta /home/ubuntu/Aula_4 da instância
# O processo leva cerca de 3 a 5 minutos.

# Nota sobre o tipo de instância:
# Contas AWS no plano gratuito (Free plan) só podem criar instâncias Free Tier. Por isso o padrão é
# m7i-flex.large (2 vCPU / 8 GB de RAM + 8 GB de swap). Funciona, porém é mais lento.
# Se a sua conta estiver no plano pago, use uma instância maior (4 vCPU / 16 GB, ~US$ 0,17/h):

terraform apply -var instance_type=t3.xlarge

# 4- Configure o acesso SSH. Execute o comando abaixo e copie a saída para o final do arquivo ~/.ssh/config
# (no Windows: C:\Users\<seu usuário>\.ssh\config). Crie o arquivo se ele não existir.

terraform output -raw ssh_config

# 5- Conecte o VSCode à instância:

# - Pressione Ctrl+Shift+P (Cmd+Shift+P no Mac) e execute "Remote-SSH: Connect to Host..."
# - Escolha "mlops-aula4" (na primeira conexão, escolha a plataforma "Linux" e confirme com "Continue")
# - Em File > Open Folder, abra a pasta /home/ubuntu/Aula_4
# - Abra um terminal no VSCode (Terminal > New Terminal). Ele já roda dentro da instância EC2.

# 6- No terminal do VSCode, execute o comando abaixo para criar os containers:

docker-compose up --build -d

# Nota: Será preciso editar 2 arquivos e colocar o nome do hostname do container do ElasticSearch, conforme mostrado nas aulas.
# Edite os arquivos pelo próprio VSCode conectado à instância.

# Nota: O container airflow_worker aparece como "Exited" no comando "docker ps -a". Isso é esperado:
# o projeto usa o LocalExecutor do Airflow, que não precisa de worker.

# 7- Abra o navegador do seu computador e acesse o Airflow para ativar a DAG:

localhost:8080

username: airflow
password: airflow

# Nota: As portas 8080, 8501 e 3000 só funcionam enquanto o VSCode estiver conectado à instância (túnel SSH).
# As portas encaminhadas aparecem na aba "Ports" do VSCode. Elas não ficam expostas na internet.

# 8- Abra o navegador e acesse a app web para interagir com o LLM (espere alguns segundos até o ElasticSearch finalizar a indexação):

localhost:8501

# Nota: A primeira pergunta demora mais (alguns minutos na instância Free Tier), pois o modelo (~1,3 GB) é baixado e carregado na memória. As seguintes são mais rápidas.

# Exemplos de perguntas:

# Can the landlord avoid liability for breaching this obligation if the state of disrepair is caused by the tenant's actions?
# Why did the plaintiff wait seven months to file an appeal?
# Can you provide more details on the clarification provided in Note 1?

# Abra o navegador e acesse o Grafana para carregar o dashboard. Siga as instruções das aulas para ajustar a configuração:

localhost:3000

username: admin
password: admin

# Envie perguntas na app de IA Generativa e monitore pelo Dashboard do Grafana.

# 9- Ao terminar, destrua a instância para não gerar custos (na pasta terraform do seu computador):

terraform destroy

# Nota: os arquivos editados na instância são apagados junto com ela. Se quiser guardá-los, copie antes
# (exemplo: arraste os arquivos do Explorer do VSCode para uma pasta do seu computador).


# Problemas comuns:

# - "Connection timed out" no SSH: o seu IP mudou (outra rede/Wi-Fi). Execute "terraform apply" novamente.
# - "address already in use" nas portas 8080/8501/3000: algo no seu computador já usa a porta
#   (por exemplo, os containers da Aula 4 no Docker Desktop). Pare esses containers locais.
# - Containers reiniciando ou muito lentos: verifique a memória com "free -h" e "docker stats".
# - Para pausar sem destruir: pare a instância no console da AWS (EC2 > Instances > Stop). Ao ligar de novo,
#   o IP muda: execute "terraform apply" e atualize o HostName no ~/.ssh/config com "terraform output ip_publico".
# - Para reenviar os arquivos do projeto do seu computador para a instância (sobrescreve os da instância):
#   terraform apply -replace=terraform_data.projeto
